## 1. BiLSTM-Attention 边抽取

**文件**：`notebooks/01_deep_learning/bilstm_attention_relation_extraction.ipynb`

将边抽取建模为事件关系分类任务，由输入层、嵌入层、双向 LSTM 层、注意力层、输出层组成。

**输入构造**：`[事件1原文] [事件1五元组] [事件2原文] [事件2五元组]` 拼接，添加类型标识符区分自然文本与结构化数据，经 Chinese RoBERTa 编码得到 768 维词向量。

**超参数**

| 参数 | 值 |
|---|---|
| 隐藏层维度 | 512 |
| 隐藏层数 | 2 |
| 初始学习率 | 2e-5（编码器） |
| 学习率调度 | Linear |
| 优化器 | AdamW |
| 最大输入长度 | 256 |
| 权重衰减 | 0.01 |
| 批次大小 | 64 |
| 训练轮数 | 50 |

**分层学习率**：BiLSTM、注意力层与全连接层使用 5 倍于编码器的学习率，加速特征适配。

**负采样**：训练集与验证集按 30% 比例随机采样负样本标注为「无关系」，测试集不做负采样以真实反映各关系类型的识别能力。

## 3. 结点抽取（SFT）

**文件**：
- `notebooks/02_llm_sft/event_extraction_qwen1.5b_prompt_ablation.ipynb`
- `notebooks/02_llm_sft/event_extraction_qwen7b.ipynb`

**超参数对比**

| 参数 | Qwen2.5-1.5B-Instruct | Qwen2.5-7B-Instruct |
|---|---|---|
| 初始学习率 | 2e-5 | 5e-6 |
| 学习率调度 | Cosine | Cosine |
| 优化器 | AdamW_torch_fused | AdamW_torch_fused |
| 最大输入长度 | 256 | 256 |
| 批次大小 | 256 | 256 |
| 梯度累积 | 4 | 4 |
| 训练轮数 | 10 | 10 |
| LoRA 模块 | q, k, v, o, gate, up | q, k, v |
| LoRA 参数 | r=32, α=64 | r=16, α=32 |

**为什么 7B 用更保守的配置**：7B 模型训练前期 loss 急速下降并维持低位，而验证集 loss 先降后升，判断为过拟合。原因是该任务对大参数模型而言，预训练能力已初步够用，训练几轮后容易记住全部训练数据。通过降低学习率、减少微调模块数量、调低 r 值有效缓解。

### 提示词消融实验

`event_extraction_qwen1.5b_prompt_ablation` 中对比两版提示词：

**Prompt A（仅格式约束）**

```
### 指令: 从儿童叙事文本中提取标准化叙事事件。严格按照格式输出。
**事件结构:** (触发词；主语；宾语；时间状语；地点状语)
缺失信息用"无"，多个主语或宾语用逗号分隔。
**示例:** ...
```

**Prompt B（附加句法分析引导）**

```
### 指令: 从儿童叙事文本中提取标准化叙事事件。
先分析句子结构，识别核心谓语动词（触发词），
再匹配施事（主语）、受事（宾语），最后提取时空成分。
!!务必严格遵循以下格式!!
...（示例增至两条）
```

差异在于 Prompt B 显式给出了「谓语 → 论元 → 时空成分」的分析顺序，并提供更多示例。

## 4. GRPO 强化学习

**文件**：
- `notebooks/03_llm_grpo/event_extraction_grpo_qwen7b.ipynb`
- `notebooks/03_llm_grpo/relation_extraction_grpo_qwen7b.ipynb`

未选用 DeepSeek-R1-Distill 系列的原因：该模型预训练阶段内置的 `<think>` 输出格式难以通过奖励函数调整，容易「过度思考」，不适合格式化输出任务。

**超参数**

| 参数 | 结点抽取 | 边抽取 |
|---|---|---|
| 初始学习率 | 1e-5 | 1e-5 |
| 学习率调度 | Cosine | Cosine |
| 优化器 | AdamW_8bit | AdamW_8bit |
| 最大输入长度 | 512 | 1024 |
| 最大输出长度 | 128 | 256 |
| 单次提示生成样本数 | 4 | 2 |
| 批次大小 | 16 | 16 |
| 梯度累积 | 4 | 2 |
| 训练轮数 | 1 | 1 |
| LoRA 模块 | q, k, v, o, gate, up, down | gate, up, down |
| LoRA 参数 | r=32, α=32 | r=16, α=16 |
| 量化 | 4-bit | 4-bit |

边抽取任务因显存限制将单次提示生成样本数降至 2，并相应精简 LoRA 配置。

### 奖励函数设计

**结点抽取**（权重 0.3 / 0.5 / 0.2）

1. `format_reward_func` — 正则校验五元组格式，按错误类型（缺括号、分号数量不符）分级惩罚
2. `field_accuracy_reward_func` — 逐字段比对预测与标注，计算字段级 F1
3. `logic_consistency_reward_func` — 校验触发词与宾语是否真实出现在原文中，抑制幻觉生成

**边抽取**（权重 0.2 / 0.5 / 0.3）

期望输出格式：`<推理过程>...</推理过程><答案>...</答案>`

1. `check_output_format` — 检查两个标签是否完整且内容非空
2. 答案正确性 — 完全正确得 1.0，否则按关系类型相似度矩阵给出部分分
3. `evaluate_reasoning_quality` — 检查推理过程是否覆盖必要判断步骤（时间重叠、目标/计划、心理引发、物理规律、反事实验证）、逻辑是否完整、是否有明确结论

奖励函数设计参考 DeepSeek-R1 技术报告中引导模型在特定标签内产生推理过程的思路。

## 5. 评估指标

**结点抽取**：精确率、召回率、F1。仅当触发词、主语、宾语、时间状语、地点状语全部正确匹配时计为正确。

大模型生成式抽取额外采用**宽松匹配准则**：抽取的五元组经词向量编码后与标注数据的余弦相似度达到阈值（0.8）即视为正确匹配。该设计用于缓解标注边界不统一（如「摔倒」vs「摔」、「一个小男孩」vs「小男孩」）带来的评估偏差。

**边抽取**：同时报告宏观与微观指标。宏观指标对所有类别赋予同等权重，反映模型在长尾类别上的表现；微观指标汇总所有预测后统一计算，反映整体表现。两者差距可用于诊断类别不均衡的影响。

## 6. 基线对比：zero-shot / few-shot / SFT

**文件**：`notebooks/02_llm_sft/baseline_zeroshot_fewshot_sft_deepseek7b.ipynb`

在同一基座模型（DeepSeek-R1-Distill-Qwen-7B）上，用相同的测试集依次评估三种设置，结果分别输出到 `0_shot/`、`2_shot/`、`finetune/` 三个目录，确保对比条件一致。

| 设置 | 说明 | 结点抽取 F1 |
|---|---|---|
| zero-shot | 仅给出格式定义，不提供示例 | 36.9 |
| few-shot (2-shot) | 提示词中加入两条示例 | 41.8 |
| LoRA SFT | 在训练集上微调 | — |

**LoRA 配置**：r=8, α=8, dropout=0.1, 模块 q/k/v/o_proj

这组实验验证了少样本提示能带来约 5 个百分点的提升，但与微调仍有明显差距。

## 7. GRPO 联合式抽取（探索性）

**文件**：`notebooks/03_llm_grpo/joint_extraction_grpo_deepseek7b.ipynb`

尝试用强化学习一次性完成结点与边的抽取。

**基座模型**：DeepSeek-R1-Distill-Qwen-7B，max_seq_length=5120，lora_rank=8

**期望输出格式**

```
<事件列表>
(触发词；主语；宾语；时间；地点)
...
</事件列表>
<关系列表>
[源事件五元组] [目标事件五元组] [关系类型]
...
</关系列表>
```

**三个奖励函数**

1. `format_reward_func` — 同时校验事件五元组与关系三元组的格式，预编译正则匹配
2. `field_accuracy_reward_func_optimized` — 事件字段级准确性
3. `relation_accuracy_reward_optimized` — 关系抽取准确性，需同时匹配两个事件与关系类型

配套实现了 `parse_model_output()` 解析函数，从标签块中还原事件与关系结构。

**结论**：受试错成本与设备资源限制，该方向未能充分展开，代码作为探索记录保留。论文中对应的表述为「联合式抽取的实验未能充分展开」。
